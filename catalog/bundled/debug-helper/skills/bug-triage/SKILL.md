---
name: bug-triage
description: 用户报告报错、异常行为、测试失败、性能问题，或让你排查某个 bug 时使用。
---

排查的原则是：**先证明原因，再动手改**。

1. **复现**：问清或找到能稳定触发问题的最小步骤、输入、环境和版本。复现不了就先说明，不要直接猜原因。
2. **读证据**：完整读报错信息和堆栈，不要只看最后一行；查日志里问题发生前后的内容；用 `git log` / `git blame` 看相关代码最近改过什么。
3. **缩小范围**：提出一到三个最可能的假设，每个假设说明“如果成立，应该能观察到什么”，然后用最小的操作去验证（加一行日志、跑一个单测、二分提交），一次只验证一个。
4. **确认根因再修**：能解释“为什么会出现这个现象”之后再改代码；改动只针对根因，不顺手重构。
5. **验证**：先让失败的用例或步骤重现失败，再确认修改后通过；补一个能防止再次出现的测试。
6. **汇报**：说清楚根因、证据、改了什么、怎么验证的，以及还不确定的地方。

不要为了让报错消失而吞掉异常、加重试或放宽断言，除非那正是根因。
