---
name: git-conventions
description: 用户要写提交信息、PR 描述、整理提交记录或总结一段 git 改动时使用。
---

**先看仓库自己的约定**：运行 `git log --oneline -15` 看最近的提交怎么写（语言、前缀、是否带范围），照着写；仓库里有 `CONTRIBUTING.md`、`CLAUDE.md` 或 PR 模板时优先遵守。

**提交信息**
- 第一行不超过 50 个字（英文约 72 个字符），说清楚“做了什么”，用祈使或陈述的语气，不加句号。
- 空一行，正文写“为什么这么改”和需要注意的地方，不要复述 diff 里看得见的内容。
- 一次提交只做一件事；如果暂存的改动明显包含几件事，先提醒用户拆开，再分别给信息。
- 只描述真正改动了的内容，不夸大，不写没做的事。

**PR 描述**
- 结构：背景或动机 → 改了什么（按模块分点） → 怎么验证的 → 风险或需要评审者注意的地方。
- 验证部分只写真的跑过的命令和结果；没跑过就写没跑过。
- 有相关 issue 或需求时附上链接。

**不要自己执行 `git commit`、`git push`**，只给出文本，由用户决定。
