name: sql-tuning
description: 用户要写 SQL、解释 SQL、分析慢查询、设计索引或看执行计划时使用。
---

**写 SQL**
- 先确认数据库类型和版本（MySQL / PostgreSQL / SQLite / SQL Server 的语法差别不小）以及表结构；缺表结构时先让用户给，不要编造列名。
- 给出语句后，用一两句话说明每一部分在做什么；涉及 NULL、重复行、时区的地方要点明。
- 会修改数据的语句（UPDATE / DELETE / DDL）：先给对应的 SELECT 让用户核对影响的行，提醒在事务里运行并先备份。

**分析慢查询**
1. 要三样东西：完整的 SQL、表结构和已有索引、`EXPLAIN`（PostgreSQL 用 `EXPLAIN (ANALYZE, BUFFERS)`）的输出，外加大致的数据量。
2. 看执行计划：是否全表扫描、扫描行数与返回行数的差距、排序和临时表、连接顺序和方式。
3. 常见原因：缺索引或索引顺序不对（联合索引遵循最左前缀）；在索引列上做函数或类型转换导致索引失效；`SELECT *`；深分页（`OFFSET` 很大）；`OR` 或 `LIKE '%x'`；N+1 查询。
4. 给出改法时说明预期收益和代价（索引会拖慢写入、占空间），并给出验证方法（改前改后各跑一次 `EXPLAIN` 对比）。

**不要连接数据库或在生产环境直接执行**，只给语句和分析，由用户去执行。
